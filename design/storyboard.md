## 画面ごとの操作項目と確認観点

### D-01 プロジェクト
- 操作: セクション折りたたみ、チェックで完了、行ホバーで 4 アイコン (編集 / 日付 / コメント / その他)、末尾「タスクを追加」、完了表示トグル
- 操作: 牛乳と卵を買う / 洗剤の詰め替え の行に折りたたみ状態のシェブロン (左余白) と件数バッジ (1/3, 0/2) を表示。D-01b で展開
- 確認観点: 長文タイトル行 (60 文字) の折り返しで操作アイコンの位置が崩れないか。サイドバーの件数表示が邪魔でないか
- 確認観点: サイドバー最下部の同期状態 (サイドバーのある全デスクトップ画面共通。4 状態は D-09d) が目に入りすぎず、見落とされもしないか

### D-01b サブタスク展開 / D-01c サブタスク追加フォーム
- 操作: 親行の左余白のシェブロンで展開・折りたたみ、子行のチェックで完了、孫の展開 (子のシェブロン)、末尾「サブタスクを追加」でインライン追加フォーム (D-01c) を開く。フォームは期限 / 優先度 / リマインダー / ラベルのツールバーと「キャンセル」/「サブタスクを追加」ボタンを持つ
- 確認観点: 1 階層 32px のインデントで階層が読めるか (孫は 64px)。フォームが行の流れを壊さないか (行の位置に差し込まれ、前後の行がずれるだけか)
- 確認観点: 件数バッジ (1/3) の位置がメタ行の末尾で邪魔にならないか。シェブロンを左余白に出したことで、シェブロンなしの行とチェックボックスの位置が揃っているか
- 確認観点: 完了した子行は D-03 と同じ「グレー文字 + 緑の塗りつぶしチェック」で表現している
- 注記: D-01 の長文テスト行は D-01b には無い (D-01 → D-01b で消えるのは仕様)

### D-02 クイック追加
- 操作: 入力中に `明日` `p1` `#買い物` `@食品` がチップ化。ツールバーで補完。プロジェクト選択は左下
- 確認観点: チップ化が入力の邪魔にならないか。Enter で追加、Shift+Enter で説明に移る想定

### D-03 タスク詳細
- 操作: タイトル / 説明の直接編集、各プロパティ行をクリックでポップオーバー、サブタスクの追加と完了、コメント投稿
- 操作: 親タスクのパンくず (サブタスクを開いたとき) は未描画
- 確認観点: パネル幅 400 で情報量が多すぎないか。プロパティの順序 (プロジェクト → 期限 → 優先度 → ラベル → リマインダー → 繰り返し)
- 確認観点: 完了したサブタスクは取り消し線ではなく「グレー文字 + 緑の塗りつぶしチェック」で表現している (pen の制約)。これで完了済みと伝わるか

### D-04 今日
- 操作: 期限切れグループの一括再スケジュール、各行の完了
- 確認観点: 期限切れなしのとき (D-04 今日 (期限切れなし)) の見出し省略が自然か
- 触って確かめる Story: `D-04 今日 (操作)` (再スケジュールと完了を実際に触れる)

### D-05 近日
- 操作: 週ストリップで日付移動、月セレクタ、各日の追加
- 確認観点: 予定なしの日 (10/15) に「タスクを追加」だけ出る表示でよいか
- 触って確かめる Story: `D-05 近日 (操作)` (週ストリップ、月セレクタ、各日の追加を実際に触れる)

### D-06 フィルターとラベル / D-06b ラベル詳細
- 操作: フィルター / ラベルの追加、件数表示、ラベル詳細へ
- 確認観点: Phase 5 のフィルターをここに同居させてよいか

### D-07 日付ピッカー / D-07b 繰り返し設定
- 操作: 自然言語入力、クイック選択、カレンダー、時刻、繰り返しプリセット、RRULE プレビュー
- 確認観点: RRULE 文字列の表示がノイズか (非表示にする選択肢あり)
- Phase 3 の実装 (D-07b): 入力欄「毎週月曜 のように入力」に書くと、入力が止まったあとに `parse_recurrence` の結果 (要約) をプレビュー行に出す。Enter か「適用」で確定。要約できる RRULE は要約を、できないものだけ RRULE 文字列を出す。プリセットは従来どおり。クイック追加では繰り返し語が期限と同系統の色のトークンになり、タスクの行には期限チップの右に繰り返しアイコン (実アプリのみ。Story では出さない)

### D-08 リマインダー / D-08b OS 通知
- 操作: 期限から / 日時指定の切替、候補の追加、追加済みの削除
- 確認観点: 通知の「完了」「後で」ボタンで足りるか
- Phase 3 の実装 (D-08): 追加したリマインダーの表示は Phase 0.5 のまま。時刻付きの期限を付けると、設定の「既定リマインダー」(初期値は同時刻) が空のリマインダーに自動で付く。時刻なしの期限で有効なのは「前日」「1 週間前」(9:00。設定で変更)
- Phase 3 の実装 (D-08b): 通知のボタンは「後で (10 分)」「完了」の順 (macOS は「オプション」メニューに畳まれ、メニュー自体のクリックは先頭の「後で」になる)。クリックでウィンドウが出てそのタスクの詳細が開く。古い通知のボタンはウィンドウを出すだけ。ボタンが届かない場合の受け皿として、画面上部に「リマインダー」の帯 (完了 / 後で / 開く / 閉じる) を出す。停止中に過ぎた分は 1 通の通知と帯にまとめる

### D-09 設定 (未ログイン) / D-09c 設定 (接続済み) / D-09b 競合バナー / D-09d 同期状態一覧 / D-09e 設定 (NAS 未接続) / D-09f 設定 (NAS 接続済み)
- 操作 (D-09 未ログイン): 説明文を読み、「Google でログイン」を押す (ブラウザが開く)
- 操作 (D-09c 接続済み): ログイン中のアカウント表示、ログアウト、今すぐ同期、Drive フォルダ変更
- 操作 (同期先セグメント): 本文先頭の「同期先」セグメント (Google Drive | Synology NAS (WebDAV) | 同期しない) で切り替える。D-09 / D-09c は Google Drive、D-09e / D-09f は Synology NAS (WebDAV) を選択した状態。「同期しない」を選ぶと同期セクションを隠す。設定の左ナビ項目は「同期」
- 操作 (D-09e NAS 未接続): URL / ユーザー名 / パスワードを入力し、「接続テスト」で結果をその場に表示、「接続」で接続する。成功すると D-09f
- 操作 (D-09f NAS 接続済み): 接続状態の確認、今すぐ同期、フォルダ変更、「切断」で D-09e に戻る
- 確認観点: クライアント ID の入力欄を廃止し、ログインボタンだけにしたことの妥当性。未接続時の説明文で何が同期されるか伝わるか
- 確認観点: 未ログイン時は同期の操作行を出さない (D-09) 構成で迷わないか。競合バナーの文言が分かるか
- 未ログイン時はサイドバーの同期状態が「同期オフ · 未ログイン」になる (D-09)。D-09b は同期エラー表示の例を兼ねる
- 確認観点 (D-09d): 同期中 / 同期済み / オフライン / エラーの 4 状態が見分けやすいか。サイドバー最下部という位置と、エラー時のクリックで再同期する想定が自然か
- 確認観点 (D-09e / D-09f): 同期先の切替位置 (本文先頭) で迷わないか。NAS の説明文 (WebDAV Server、HTTPS、外出先アクセス) が十分か。パスワードの保存先 (OS キーチェーン) が明記されているか
- 確認観点: 外観 / 日付と時刻 / アカウント のペインは未描画。項目は M-07 を参照
- 注記: 同期先の抽象化 (StorageBackend: Google Drive / WebDAV) と Phase 4b は設計書の後続 PR で反映

### D-10 ボード
- 操作: カードのドラッグ、列追加
- 確認観点: ドラッグ中のカード (影と傾き) とドロップ位置 (赤い線) を 1 枚で表現
- 確認観点: カードの情報量 (タイトル + 期限 + 優先度) で足りるか
- 確認観点: 「完了」列は通常のセクションとして扱う (完了タスクの既定非表示とは別)。
- 確認観点: 「セクションを追加」列は幅 200 (他の列は 280)。1440 幅に収めるための寸法で、実装時は横スクロール前提で揃える

### D-11 状態 (D-11a 空のプロジェクト / D-11b 読み込みエラー / D-11c 要修正行)
- 確認観点: エラー文言が次の行動 (再試行 / 場所を開く / Excel で開く) を示しているか

### D-12 初回起動 / D-12b Google 接続 / D-12d NAS / D-12c 受信トレイ
- 操作: 保存先の選択 (D-12) → 同期先の選択 (D-12b。ステップ 2 の名前は「同期先」) → 受信トレイ作成 (D-12c)
- 操作 (D-12b): 同期先セグメント (Google Drive | Synology NAS (WebDAV) | 同期しない)。Google Drive は「Google でログイン」ボタンのみ (クライアント ID の入力は廃止)、またはスキップ
- 操作 (D-12d): 同期先セグメントで Synology NAS (WebDAV) を選んだ状態。URL / ユーザー名 / パスワードを入力して「接続して次へ」、またはスキップ。ヘッダの説明文は D-12b と共通の同期先に中立な文言
- 確認観点: 3 ステップで迷わないか。スキップは省略できる D-12b / D-12d にだけ置く。同期先の選択がステップ 2 に収まっているか

### D-13a / D-13b 狭いウィンドウ (幅 750 未満)

- 確認観点: 幅 400 でも一覧・見出し・上の帯がはみ出さないか
