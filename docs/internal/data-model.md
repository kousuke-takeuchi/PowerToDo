# データ

PowerToDo が読み書きするファイルの形である。共有するもの (データフォルダ) と、端末ごとのもの (アプリのデータの場所) に分かれる。

## データフォルダ

```text
<データフォルダ>/
  _PowerToDo.xlsx              共通ファイル
  受信トレイ.xlsx               受信トレイ (この名前のプロジェクトだけが受信トレイ)
  <プロジェクト名>.xlsx         プロジェクト 1 つにつき 1 ファイル
  _comments/<プロジェクト名>.<No>.jsonl   タスクごとのコメントと添付の記録
  _attachments/<sha256>.<拡張子>          添付のファイル
  archive/                     削除、競合で負けた側、終了時に退避したファイル
  <名前> (競合 yyyy-mm-dd hhmm).xlsx      同期の競合コピー (同期しない)
```

シートと列は、名前で探す。列の順番が変わっても読める。知らない列とシートの扱いは、下の各節にある。

## プロジェクトのファイル (`<プロジェクト名>.xlsx`)

### シート「タスク一覧」

1 行目が見出し、2 行目からがタスクである。A 列から R 列が決まった列 (`src-tauri/src/store/project_book.rs` の `HEADERS`) である。

| 列 | 見出し | 中身 |
|---|---|---|
| A | No. | プロジェクトの中の番号。消しても使い回さない |
| B | プロジェクト | プロジェクトの名前 |
| C | カテゴリ | セクションの名前。空はセクション無し |
| D | タスク | タスク名 |
| E | 担当 | 担当者 |
| F | 優先度 | `高` (p1)、`中` (p2)、`低` (p3)。空は p4 |
| G | 進捗 | 0 から 100。100 が完了 |
| H | 開始 | 開始日 |
| I | 終了 | 期限。時刻を含むことがある |
| J | 日数 | 開始から終了までの営業日 (土日と祝日を除く) |
| K | 備考 | 説明 |
| L | 親No. | サブタスクの親の No.。空は一番上の段 |
| M | ラベル | カンマ区切り |
| N | 繰り返し | RRULE の本体 (下の「繰り返し」) |
| O | リマインダー | カンマ区切りのコード ([デスクトップ](../03-desktop.md#リマインダーと通知)) |
| P | 並び順 | 同じ段の中の順番 |
| Q | 作成日時 | |
| R | 完了日時 | |

- R 列より右の列は、アプリが知らない列として残す。書き戻すときは、元の順で決まった列の後ろに書く。
- アプリが使う追加の列もこの場所に置く。例: `今日の並び` (今日の画面での手動の並び)。
- 形の壊れた行は「要修正」として出し、アプリからは編集できない。書き戻すときは、セルをそのまま正しいタスクの後ろに書く (行の番号は変わる)。
- 「タスク一覧」と「設定」のほかのシートと、書式は、書き戻しで残らない。

### シート「設定」

1 行目が見出し、2 行目が値である (見出し行、開始行、開始列、終了列)。F4 の「カテゴリ」、G4 の「担当」、H4 の「優先度」の下に、選べる値の一覧が並ぶ。Qiita の形に合わせたものである。

### 繰り返し

「繰り返し」列には RRULE の本体だけを書く。`DTSTART` は書かず、計算のたびに今の期限から組み立てる。

| 例 | 意味 |
|---|---|
| `FREQ=WEEKLY;BYDAY=MO` | 毎週月曜 |
| `FREQ=MONTHLY;BYMONTHDAY=-1` | 毎月末 |
| `FREQ=DAILY;INTERVAL=3;X-FROM=COMPLETED` | 完了した日から 3 日ごと |

`X-FROM=COMPLETED` が無ければ、期限から数える。Excel で直接書いてもよい。

## 共通ファイル (`_PowerToDo.xlsx`)

| シート | 列 |
|---|---|
| プロジェクト | 名前 / 色 / 並び順 / お気に入り / 受信トレイ / アーカイブ |
| ラベル | 名前 / 色 / 並び順 |
| フィルター | 名前 / クエリ / 並び順 (空で書く。まだ読まない) |
| 祝日 | 日付 / 名称 |
| 設定 | キー / 値 |

- 色は、画面が使う CSS 変数の文字列 (例: `var(--color-priority-2)`) である。
- お気に入り、受信トレイ、アーカイブは TRUE / FALSE である。古い版は「アーカイブ」列を知らない列として文字のまま残し、新しい版はそれを読める。
- 「設定」のキー: 表示名、週の開始、タイムゾーン、既定リマインダー、時刻なしの通知時刻、閉じたときトレイに残す、通知。画面ごとの「表示」の設定 (並び替え、グループなど) も、`表示:<画面>` のキーでここに入る。プロジェクトの Google カレンダーは `カレンダー:<プロジェクト名>` のキーで、値は `<メール>|<カレンダー ID>|<色>|<名前>` である (名前は最後なので `|` を含んでよい)。プロジェクトの名前を変えると、キーも付け替わる。削除すると消える。古い版は知らないキーとして残す。
- 書き戻しで残すもの: プロジェクトとラベルの知らない列、日付でない祝日の行、知らないキーの設定の行。残さないもの: 上の 5 つ以外のシート、フィルターの行、見出しが空か重なった列、書式。

## コメントと添付の記録 (`_comments/`)

タスクごとに 1 つの JSON Lines のファイルである。名前は `<プロジェクト名>.<No>.jsonl`。1 行が 1 つの出来事で、書き足すだけで前の行は書き換えない。

```json
{"id":"1792929845000-3f2a…","op":"add","at":"2026-10-25T21:04:05+09:00","author":"たろう","text":"見積もりを送った","files":[{"hash":"3f2a…9c","ext":"png","name":"見積もり.png","type":"image/png","size":183204,"w":1600,"h":900}]}
{"id":"1792930200000-9c1d…","op":"edit","target":"1792929845000-3f2a…","at":"2026-10-25T21:10:00+09:00","author":"たろう","text":"見積もりを送った (税込)"}
{"id":"1792930320000-07be…","op":"delete","target":"1792929845000-3f2a…","at":"2026-10-25T21:12:00+09:00","author":"たろう"}
{"id":"1792930500000-a4e0…","op":"note-attach","at":"2026-10-25T21:15:00+09:00","author":"たろう","files":[{"hash":"…","ext":"pdf","name":"図面.pdf","type":"application/pdf","size":52011}]}
{"id":"1792930560000-5b77…","op":"note-detach","target":"1792930500000-a4e0…","at":"2026-10-25T21:16:00+09:00","author":"たろう"}
```

| op | 意味 |
|---|---|
| `add` | コメントを足す。`files` は添付 (無くてもよい) |
| `edit` | `target` のコメントを直す。`files` が無ければ添付はそのまま、あれば丸ごと差し替える |
| `delete` | `target` のコメントを消す |
| `note-attach` | 説明に添付を 1 つ足す |
| `note-detach` | `target` の `note-attach` を外す |

- `id` は、書いた時刻のミリ秒 (13 桁) と、16 進 16 桁の乱数を `-` でつないだものである。時刻の順に並ぶ。表示するときは `id` の順に読む。
- 読めない行は飛ばす。2 台の記録を合わせるときは、知らない `op` の行もそのまま残す。
- v0.5.0 より前の版は、合わせるときに `note-attach` と `note-detach` の行を捨てる。
- プロジェクトの名前を変える、タスクを移す、消すと、記録のファイルも名前を変えるか `archive/` へ移す。

## 添付のファイル (`_attachments/`)

- 名前は中身の SHA-256 (16 進 64 文字) に、元の拡張子を付けたものである (拡張子の無いファイルは付けない)。
- 一度置いたファイルは書き換えない。同じ中身は 1 つになる。
- 一時的な名前で書いてから名前を変える。書きかけのファイルは残らない。
- 元の名前、種類、大きさは、上の記録の `files` に持つ。

## アプリのデータの場所 (端末ごと)

macOS は `~/Library/Application Support/app.powertodo/` である。同期しない。

| ファイル | 中身 |
|---|---|
| `settings.json` | `dataDir` (データフォルダ)、`sync` (同期先、NAS の URL とユーザー、Google のメールアドレス)、`updates`、`autostart`、`startView`。既定の値は書かない |
| `sync.json` | 同期の記録 (同期先、前回の同期の時刻、ファイルごとの版とハッシュ) |
| `sync-base/` | 前回の同期のときのファイルの中身 (タスクごとに合わせるための土台) |
| `calendar.json` | Google カレンダー用にログインしているアカウントのメールアドレスと、カレンダーごとの前回の取り込み (予定、時刻)。トークンは入れない |
| `fired.json` | 届けたリマインダーの記録。消すと、直近 24 時間の分がもう一度出ることがある |
| `tailscale/` | 中の Tailscale の状態 |
| `.window-state.json` | ウインドウの大きさ、位置、最大化 (window-state プラグイン。デスクトップだけ)。置き場所はアプリの設定の場所 (`app_config_dir`) で、macOS と Windows ではここと同じ。Linux では `~/.config/app.powertodo/` |

NAS のパスワードと Google のトークン (同期用と、カレンダーのアカウントごとのもの。サービス名 `app.powertodo.gcal`、アカウント名はメールアドレス) は、OS のキーチェーンに置く。ファイルには書かない。
