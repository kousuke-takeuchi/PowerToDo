# Phase 0: pen デザインと操作確認

作成日: 2026-10-13
前提: `2026-10-13-powertodo-overall-design.md` (全体設計)
状態: ユーザー承認済み (会話での設計レビュー)。本ファイルのレビュー待ち。

## 1. 目的

実装に入る前に、全 Phase の画面を pen.dev 上に起こし、画面ごとの操作性をユーザーが storyboard で確認する。
ここで固めた画面構成と操作項目を Phase 1 以降の UI 実装の基準にする。

成果物
- `design/powertodo.pen`: 全画面のデザイン
- `design/storyboard.md`: 画面一覧、各画面の操作項目、画面間の遷移表
- 全体設計 spec の決定ログに、確認で出た修正点を追記

## 2. デザイン方針

- Todoist に寄せる。左サイドバー (幅 280px)、中央リスト (最大幅 800px、中央寄せ)、右にタスク詳細パネル (幅 400px、開閉)
- 配色・寸法は pen の変数にする: `$bg`, `$bg-sidebar`, `$text-primary`, `$text-secondary`, `$border`, `$accent` (Todoist 赤系), `$priority-1`〜`$priority-4`, `$spacing-*`
- ライト / ダークを theme 軸 `mode` で定義する
- フォント: 日本語は Noto Sans JP、英数は Inter
- デスクトップは 1440×900。ウィンドウ最小 960×600 の縮小版を 1 枚
- モバイルは 390×844。下部タブ (今日 / 近日 / 検索 / 一覧) + ドロワー
- 繰り返す UI (タスク行、サイドバー項目、チップ、ボタン) は reusable component にして instance で配置する
- 画面はすべて document 直下の frame。`clip: true`。作業中は `placeholder: true`
- InfoDesk の `design.pen` には触れない。新規ファイルを作る

## 4. 進め方

1. 変数とテーマを定義する
2. component を作る: タスク行、サイドバー項目、優先度チップ、ラベルチップ、日付チップ、ボタン、入力欄、セクション見出し
3. D-01 → D-03 → D-02 → D-04 → D-05 の順に主要画面を作り、各画面ごとにスクリーンショットで確認する
4. 残りのデスクトップ画面、ダーク 3 枚、モバイル 7 枚
5. `design/storyboard.md` を書く
6. ユーザーが pen.dev の storyboard で操作性を確認し、修正点を返す。修正は既存ノードを更新する (作り直さない)
7. 修正を取り込んだら Phase 0 完了。全体設計 spec の決定ログに修正点を追記する

## 5. storyboard.md の形式

```
## 画面一覧
| No | 名前 | pen ノード名 | 対応 Phase |

## 遷移表
| 起点画面 | 操作 | 遷移先 | 備考 |

## 画面ごとの操作項目
### D-01 プロジェクト
- 操作: ...
- 確認観点: ...
```

画面間リンクは pen の API にないため、遷移表を見てユーザーが pen.dev 上で必要な分だけ張る。

## 6. 完了条件

- 上記の全画面が `powertodo.pen` にあり、`placeholder: true` が残っていない
- 各画面でレイアウト崩れ、はみ出し、コントラスト不足がない (pen の `Get` でクリップ問題を確認、スクリーンショットで視覚確認)
- `design/storyboard.md` がある
- ユーザーが操作性を確認し、修正点を取り込んだ
