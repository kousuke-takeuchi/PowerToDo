# Phase 0.5: Storybook による操作性確認

作成日: 2026-10-13
前提: `2026-10-13-powertodo-overall-design.md` (全体設計)、`2026-10-13-phase0-pen-design.md` (Phase 0)、`design.pen`、`design/storyboard.md` (画面一覧・遷移表・確認観点)
状態: 会話で設計合意済み。本ファイルのレビュー待ち。

## 1. 目的

pen で起こした画面を React コンポーネントにして Storybook で動かし、ユーザーがブラウザで触って操作性を確認する。ここで作るコンポーネントは Phase 1 以降の UI にそのまま使う。

成功基準
- `npm run storybook` で 40 画面すべてと主要コンポーネントがカタログに並び、ライト / ダークと幅 (1440 / 960 / 390) を切り替えられる
- 開閉・選択・切替の操作がクリックで動く (下記 §5 の範囲)
- ユーザーが Story 名で指摘を返せる

対象外 (Phase 1 以降)
- データの追加・更新・削除、保存、同期などの状態変化を伴うロジック
- Tauri command の呼び出し、xlsx の読み書き
- ドラッグ & ドロップの実装 (見た目のみ)
- モバイルのスワイプジェスチャー (見た目のみ)
- 自動テスト (Storybook の interaction test は Phase 1 で検討)

## 2. 技術

| 項目 | 決定 |
| --- | --- |
| プロジェクト雛形 | Tauri 2 の `create-tauri-app` (React + TypeScript + Vite テンプレート)。`src-tauri/` は雛形のまま触らない |
| UI | React + TypeScript + Tailwind CSS。コンポーネントライブラリは使わない (pen のデザインをそのまま再現するため) |
| カタログ | Storybook (Vite ビルダー)。`src/` と同居。`npm run storybook` で起動 |
| アイコン | lucide-react (pen と同じ lucide アイコン名) |
| フォント | Noto Sans JP (Google Fonts を Storybook の preview-head で読み込む。配布版での同梱は Phase 1) |
| バージョン | 雛形作成時点の最新安定版。計画書で `npm install` の結果を記録する |

- `components/` は props だけで描画し、内部状態を持たない (チェック状態や展開状態は props)
- `views/` は操作性確認に必要な最小の内部状態だけ持つ (§5)
- `types/model.ts` は Phase 1 の Rust 側 JSON と同じ形にする。Phase 1 で Tauri command の戻り値をそのまま流し込めるようにする

## 4. デザイントークン

pen の変数をそのまま CSS カスタムプロパティにする。名前は pen と同じ。

| pen | CSS | Tailwind |
| --- | --- | --- |
| `bg`, `bg-sidebar`, `bg-hover` | `--color-bg` … | `bg-bg`, `bg-bg-sidebar`, `bg-bg-hover` |
| `text-primary`, `text-secondary`, `text-muted` | `--color-text-primary` … | `text-text-primary` … |
| `border`, `accent`, `accent-soft`, `priority-1`〜`4`, `success`, `danger` | 同様 | 同様 |
| `space-1`〜`space-6`, `radius` | `--space-1` …, `--radius` | Tailwind の既定スケール (4 / 8 / 12 / 16 / 24) と `rounded-[var(--radius)]` |

- ダークは `html[data-theme="dark"]` でカスタムプロパティを差し替える。pen の dark 値 (Task 10 で調整した `text-muted` #8F8F8F、`success` #2E9E4F を含む) を使う
- フォントは `--font-body: "Noto Sans JP"`

## 5. 操作性確認の範囲 (方針 A)

Story の中で動くもの (view の内部状態)
- サイドバー / ドロワーの項目選択の見た目 (選択行のハイライトのみ。画面遷移は Story を切り替える)
- セクションの折りたたみ、サブタスクの展開 / 折りたたみ (D-01 ↔ D-01b)、インラインフォームの開閉 (D-01b ↔ D-01c)
- チェックボックスのオン / オフ (見た目だけ。件数は変わらない)
- クイック追加ダイアログ、タスク詳細パネル、日付 / 繰り返し / リマインダーのポップオーバー、設定ダイアログ、下部シート、ドロワーの開閉
- 設定の同期先セグメント切替 (Google Drive / NAS / 同期しない で本文が切り替わる)、タブバーの選択、週ストリップの日付選択
- ホバー時の行アイコン表示 (TaskRow の Actions)

動かないもの
- タスクの追加・削除・移動、完了による一覧からの消去、保存、同期
- 入力欄のバリデーション、日付の自然言語解析
- ドラッグ、スワイプ、通知

## 6. Stories

- 画面 Story は `design/storyboard.md` の画面一覧と 1 対 1。Story 名は pen のノード名 (例 `D-01 プロジェクト`, `M-01b サブタスク展開`)。グループは `Screens/Desktop`, `Screens/Dark`, `Screens/Mobile`
- 各画面 Story は `AppShell` にモックデータを渡して描く。モバイル Story は幅 390 の枠内に描く
- コンポーネント Story は状態バリアントを並べる: TaskRow (通常 / 完了 / 期限切れ / サブタスクあり / 展開 / 長文)、SyncStatus (4 状態 + 同期オフ)、Checkbox、chips、Button、TextField、Segmented、TabBar
- Storybook のツールバーでテーマと幅を切替。ダーク Story は D-01 / D-03 / D-04 の 3 枚を明示的に用意し、他はツールバーで確認
- 遷移表の「→」は Story 間のリンクとして各 Story の説明 (docs) に書く (Storybook の `parameters.docs.description`)

## 7. 確認の進め方

1. `npm install && npm run storybook` → ブラウザで `http://localhost:6006`
2. `Screens/` を上から順に開き、`design/storyboard.md` の「画面ごとの操作項目と確認観点」に沿って触る
3. 指摘は「Story 名 + 内容」で返す。まとめて 1 PR で修正し、pen 側も同じ内容を反映する (pen と React の二重管理は Phase 0.5 の間だけ。Phase 1 以降は React が正本、pen は参照用)

## 8. 完了条件

- 40 画面の Story がすべてあり、各画面が pen と同じ構成で描かれている (pen のスクリーンショットと並べて差がないことを計画の最終タスクで確認)
- §5 の操作が動く
- `npm run build-storybook` が警告なしで通る
- ユーザーが確認し、指摘を取り込んだ
