## 1. 目的と範囲

所有者の言葉 (2026-10-25):
- Todoist と操作性がかなり違うように感じた
- 見た目もまねる。範囲は「配置と密度まで」。色の基調とアイコンは PowerToDo のまま
- アニメーションもまねる
- ウィンドウが小さいときの見た目も確かめる

作り直しは 4 つに分け、それぞれ設計書 → 計画 → 実装の PR にする。順番は ④ → ① → ② → ③。本書は ④。
- ④ 見た目: 配置と密度と動き。本書
- ① タスクの詳細を画面中央のダイアログにする
- ② 行の操作: その場でタスク名を直す、マウスを乗せたときのボタンを動かす
- ③ ドラッグ: 並べ替え、セクション間の移動、字下げ、セクションとプロジェクトの並べ替え、キー

含むもの (デスクトップだけ):
- 文字、行、チェック、2 段目、見出し、上の帯、セクションの見出し、左の一覧、「タスクを追加」の見た目
- マウスを乗せた行の見た目: ドラッグの持ち手とボタンを出す。押したときの動きは ② と ③ で付ける
- 動き: マウスを乗せたとき、セクションの開け閉め、左の一覧の開け閉め、完了
- 完了したときの「元に戻す」付きのお知らせ
- 狭いウィンドウのときの左の一覧

含まないもの:
- iPhone の画面 (別の作業で寄せる)
- Todoist のロゴ、アイコンの素材、名前。アイコンは今の lucide のまま
- 色の基調 (今の値がすでに Todoist に近い)
- タスクの詳細、ドラッグ、その場での編集の動き (①〜③)

成功基準:
- 幅 1512 で Todoist と PowerToDo の今日・プロジェクトの画面を並べて撮ると、次が ±2pt で合う: 左の一覧の幅、中央の列の幅と位置、1 段と 2 段の行の高さ、チェックの大きさ、字下げの幅
- 文字は OS の標準の文字になる。Mac はヒラギノ、Windows は Yu Gothic UI
- マウスを乗せると、持ち手とボタンがすぐ出て、チェックの中に灰色のチェックが出る
- 完了すると約 0.25 秒後に行が消え、左下に「元に戻す」付きのお知らせが出る。押すと戻る
- 幅 750 未満では左の一覧が隠れ、開くと画面を暗くした上に重なって出る
- ダークテーマと動きを減らす設定 (prefers-reduced-motion) でも崩れない

## 2. 文字と寸法

- 文字: `--font-body` を OS の標準にする: `-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Segoe UI", "Yu Gothic UI", "Noto Sans JP", system-ui, sans-serif`
- 大きさ (Todoist の写真と並べて、実装で最終値を合わせる):

| 部分 | 今 | 案 |
|---|---|---|
| タスク名 | 14 | 14 (OS の文字で今より大きく見える。写真で合わなければ 15) |
| 2 段目 (期日、プロジェクト名、数) | 12 | 12 |
| 画面の題名 | 24 前後 | 26 太字 |
| 題名の下の行 (件数) | 題名の横 | 題名の下、13、灰色 |
| セクションの名前 | 14 太字 | 14 太字 |
| 左の一覧の項目 | 14 | 14、件数は 12 灰色 |

- 行の高さ: 1 段 約 43、2 段 約 59。行の間は 1 本の区切り線 (今と同じ)
- 字下げ: 1 段 28 (今は 32)
- 中央の列: 最大 800 で、左の一覧を除いた領域の真ん中 (今と同じ)
- 左の一覧: 幅 280 (今と同じ)

## 3. 部品ごとの見た目

### 3.1 チェック (`Checkbox`)
- 直径 18 (今は 20)、縁 2 (今は 1.5)
- 優先度 1〜3 は縁の色に加えて、同じ色の薄い塗り (約 10%)。4 は灰色の縁で塗りなし
- マウスを乗せると、丸の中に灰色のチェックを出す (完了の予告)
- 完了の動きは今のまま (縁が膨らみ、緑に塗られてチェックが描かれる)。動きの長さは §4 に合わせる

### 3.2 タスクの行 (`TaskRow` の desktop)
- 2 段目の左: 期日、繰り返し、ラベル、サブタスクの数。順は今のまま
- 2 段目の右端: プロジェクトをまたぐ画面 (今日・近日・ラベル) で、プロジェクト名 (セクションがあれば「プロジェクト / セクション」) と色付きの「#」を右寄せで出す。今は期日の後ろに並んでいる
- マウスを乗せた行:
  - チェックの左 (約 29 左) に 6 点の持ち手を出す。押しても何もしない (③ で付ける)
  - 1 段目の右に、編集・日付・コメント・「…」を出す。「…」は今のまま。ほかの押したときの動きは ② で付ける
  - 行の背景は変えない (今は変えている)
- キーボードで選んだ行: 左の太線をやめ、角の丸い薄い枠にする

### 3.3 画面の見出しと上の帯
- 上の帯 (高さ約 48): 左に戻る・進む (今の履歴で動く範囲。無ければ出さない)、右に「表示」と「…」
- 今の見出しの右にある「表示」「並び替え」「…」は、上の帯の右に移す。「並び替え」は「表示」のメニューの中に入れる
- 題名の下の行: 「✓ N 件のタスク」(今日・近日・プロジェクト)。今日の日付の表示は、今日の画面のセクション名 (「10月25日・今日・日曜日」) に任せる

### 3.4 セクションの見出し
- 「∨」は列の左外に出す。名前は太字。右端に操作 (今日の画面の「再スケジュール」は赤) を同じ行に置く。今は区切り線の下の別の行にある
- 件数の小さな数字は今のまま

### 3.5 左の一覧
- 選んでいる項目: 背景を `--color-accent-soft` (薄い赤) にし、文字・アイコン・件数を `--color-accent` (赤) にする。今は灰色の背景
- プロジェクト: 色の点をやめ、色付きの「#」(lucide の `Hash`) にする。受信トレイは今のアイコンのまま
- 「タスクを追加」: 赤い丸に白い「+」(塗りの丸)、文字は赤の太字
- 項目の高さと余白は Todoist の写真に合わせる (1 項目 約 34)

### 3.6 「タスクを追加」の行 (一覧の末尾)
- 赤い「+」と灰色の文字 (今と同じ)。押したときの入力欄は今のまま (その場の入力欄の作り直しは ②)

## 4. 動き

`src/motion.tsx` の `useMotionTiming` を使い、動きを減らす設定ではすぐ切り替える (今と同じ決まり)。

| 操作 | 今 | 案 |
|---|---|---|
| 行にマウスを乗せる | ボタンがふわっと出る | 持ち手・ボタン・チェックの中の灰色のチェックを、すぐ出す (動きなし) |
| セクションの開け閉め | 0.2 秒で高さが動き、矢印が回る | すぐ切り替える。矢印は「∨」と「>」の差し替え |
| サブタスクの開け閉め | 0.2 秒で高さが動く | すぐ切り替える (セクションに合わせる) |
| 左の一覧を隠す・出す | (今の動き) | 約 0.3 秒ですべらせ、中央の列も一緒に真ん中へ動かす |
| 完了 | 少し残ってから消える (`LEAVE_DELAY_MS`) | 約 0.25 秒残してから消し、下の行を約 0.1 秒で詰める。左下にお知らせ (§5) |
| 狭いウィンドウで左の一覧を開く | (§7) | 暗い背景と一緒に、左から約 0.2 秒ですべり出す |

## 5. 完了のお知らせ

- 完了すると、左下に黒いお知らせを出す: 「1 件のタスクを完了しました 元に戻す ×」
- 続けて完了すると件数を足す (「2 件の…」)。お知らせは 1 つ
- 「元に戻す」は、そのお知らせに入っている全部のタスクを未完了に戻す (今の完了の取り消しと同じ操作)
- 約 5 秒で消える。マウスが乗っている間は消さない
- 繰り返しのタスクの完了も同じお知らせを出す。元に戻すと、次の回への進みも戻す (今の完了の取り消しで戻るかを、実装の計画で確かめる)
- 今日・近日・ラベル・プロジェクトのどの画面でも出す。キーボードの `e` で完了したときも出す

## 6. 見た目の基準と確かめ方

- 見た目の基準は `design.pen` と Storybook の画面 (Screens/Desktop) の両方。今と同じく、pen は見た目の参照、Storybook は操作の確認に使う
- `design.pen` を更新する:
  - 対象: デスクトップの D-01・D-01b・D-01c・D-04・D-05・D-06・D-06b・D-13 (ダークの 3 枚を含む)
  - 更新する点: §2・§3 の文字と寸法、チェック、2 段目の右寄せ、上の帯、セクションの見出し、左の一覧
  - 新しい画面: マウスを乗せた行、完了のお知らせ、狭いウィンドウで左の一覧を開いた状態。`design/storyboard.md` の画面一覧に足す
  - pen は Pencil の MCP で書く。書き込み先は Pencil の今開いている画面なので、作業の前に、この作業ブランチの `design.pen` が開いていることを確かめる。保存は所有者が ⌘S で行う
  - main の作業場所の `design.pen` には、まだ commit されていない変更がある。これには触らない。作業ブランチの `design.pen` だけを書く
- Storybook に足す:
  - マウスを乗せた行
  - 完了のお知らせ
  - 狭いウィンドウ (幅 700) で左の一覧を開いた状態
- 確かめ方: 実装の終わりに、幅 1512 で Todoist と PowerToDo の同じ種類の画面を撮り、§1 の成功基準の寸法を並べて比べる。PowerToDo は Storybook を Chrome の headless で撮る。写真は PR に貼らない (所有者の Todoist のデータが写るため)。比べた数値だけを PR に書く

## 7. 狭いウィンドウ

- 左の一覧を隠す幅を 1100 から 750 に下げる (`useShellWidth`)
- 750 以上: 左の一覧 280 と中央の列。中央の列は 800 に届かなければ縮む
- 750 未満:
  - 左の一覧は隠し、細いアイコンの帯 (`SidebarRail`) も出さない
  - 開閉のボタンを上の帯の左 (戻る・進むの左) に出す
  - 開くと、画面を暗くした上に重なって出る (今の引き出しを使う)。Esc か暗い所を押すと閉じる
- ウィンドウの最小の幅を 960 から 400 に下げる (`tauri.conf.json` の `minWidth`)。今の 960 のままでは 750 未満にできない。Todoist は幅 400 まで崩れずに縮む
- 幅 400〜750 で、中央の列、上の帯、ダイアログ類 (クイック追加、検索、設定) がはみ出さないようにする
- 幅 960 の Story (D-13) は、幅 700 と 400 の Story に置き換える

  - 狭い幅の判定 (750 の境目)

手動 (PR 本文のチェックリスト):
- Mac で今日・プロジェクト・近日を開き、§1 の寸法を Todoist と並べて確かめる (数値を PR に書く)
- 行にマウスを乗せると、持ち手・ボタン・灰色のチェックがすぐ出る
- セクションとサブタスクの開け閉めが、すぐ切り替わる
- 完了 → 約 0.25 秒で消える → お知らせ → 「元に戻す」で戻る。2 件続けて完了すると「2 件」

- ダークテーマと、動きを減らす設定で崩れない
- Windows で文字が Yu Gothic UI になる
