# PowerToDo 全体設計

作成日: 2026-10-13
状態: ユーザー承認済み (会話での設計レビュー)。本ファイルのレビュー待ち。

## 1. 目的と範囲

Excel (xlsx) ファイルをデータベースとして使う、Todoist 風の個人用 ToDo アプリを作る。
仕事のタスクも買い物メモも同じアプリで扱う。

- 対象 OS: Windows / macOS / Ubuntu (デスクトップ)、iOS / Android (モバイル)
- 1 プロジェクト = 1 xlsx ファイル。形式は Qiita 記事「エクセル七つ道具ではじめるシンプルなタスク管理」に準拠し、末尾に列を追加する (調査メモ: `docs/research/2026-10-13-excel-format-qiita.md`)
- アプリが正本。Excel は閲覧と軽い編集用。Excel で編集した値はアプリが読み戻す
- 同期は Google Drive API を直接使う。ローカルキャッシュを正本にして定期同期する
- Todoist の機能は個人用途に関わるものを全て実装する。対象外: 共有・共同編集、カルマ、添付ファイル、外部連携 (メール・カレンダー)、位置情報リマインダー

### 成功基準

- 3 つのデスクトップ OS と 2 つのモバイル OS で同じ xlsx を読み書きでき、Drive 経由で相互に反映される
- Excel / LibreOffice で xlsx を開いても Qiita 記事と同じ見た目 (条件付き書式含む) で読める
- Todoist の日常操作 (クイック追加、今日・近日、サブタスク、ラベル、繰り返し、リマインダー) がキーボードだけで完結する

## 2. 技術選定

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| アプリ基盤 | Tauri 2 | 3 デスクトップ OS + iOS / Android を 1 コードベースで。バイナリが小さい |
| コア言語 | Rust | xlsx 処理、ドメインロジック、同期を 1 か所に置き `cargo test` で検証する |
| xlsx 読み | `calamine` | 純 Rust、xlsx 読み取り |
| xlsx 書き | `rust_xlsxwriter` | 純 Rust、条件付き書式・日付セル・入力規則を出力できる。毎保存でファイル全体を生成し直す |
| UI | React + TypeScript + Tailwind | Tauri の標準構成。pen の `html-tailwind` 書き出しと相性がよい |
| 認証 | OAuth 2.0 デスクトップフロー (PKCE) | `oauth2` crate。トークンは OS キーチェーン (`keyring` crate) |
| HTTP | `reqwest` | Drive API 呼び出し |
| ファイル監視 | `notify` | Excel での外部編集、Drive からの更新を検知 |

バージョンは実装計画の時点で `cargo add` / `npm install` の結果に従う。本書では固定しない。

### 検討して採用しなかった案

- Electron: バイナリが大きい。モバイル非対応
- Flutter: xlsx ライブラリが弱い。Tauri と二重投資になる
- Python + openpyxl: xlsx 処理は強いが Todoist 風 UI の構築コストが高い
- TypeScript コア (exceljs を WebView 内で実行): 大きな xlsx 処理が UI スレッドを塞ぐ。OAuth トークンを WebView 側で持つことになる
- Expo (React Native) で別のモバイルアプリ: React でも DOM ではないため UI は書き直し。Rust コアを呼ぶには uniffi が必要で重い
- Google Drive デスクトップ版の同期フォルダに任せる: Ubuntu に公式クライアントがなく、モバイルでも使えない
- .xlsm (VBA マクロ) を維持: ライブラリで再保存するとマクロと書式が壊れやすい

## 3. xlsx ファイル形式

### 3.1 プロジェクトファイル `<プロジェクト名>.xlsx`

シートは「タスク一覧」と「設定」の 2 枚。

#### シート「タスク一覧」

1 行目が見出し、2 行目以降がデータ。A〜K 列は Qiita 記事と同じ。L 列以降は拡張。

| 列 | 見出し | 型 | 備考 |
| --- | --- | --- | --- |
| A | No. | 整数 | ファイル内で一意。欠番は再利用しない |
| B | プロジェクト | 文字 | ファイル名 (拡張子なし) と同じ値。Excel で見たときの分かりやすさのため |
| C | カテゴリ | 文字 | Todoist のセクション。空はセクションなし |
| D | タスク | 文字 | タスク名 |
| E | 担当 | 文字 | 既定は共通ファイルの「自分の表示名」 |
| F | 優先度 | 高 / 中 / 低 / 空 | P1 / P2 / P3 / P4 に対応 |
| G | 進捗 | 整数 0〜100 | 100 で完了 |
| H | 開始 | 日付 | 任意 |
| I | 終了 | 日付または日時 | Todoist の期限。任意。時刻付きは日時セル |
| J | 日数 | 整数 | アプリが営業日数を計算して値を書く。Excel 式ではない |
| K | 備考 | 文字 | Todoist の説明。複数行可 |
| L | 親No. | 整数 | サブタスクの親の No.。空はトップレベル |
| M | ラベル | 文字 | カンマ区切り。共通ファイルのラベル一覧を参照 |
| N | 繰り返し | 文字 | RFC 5545 の RRULE (例 `FREQ=WEEKLY;BYDAY=MO`)。空は繰り返しなし |
| O | リマインダー | 文字 | 絶対時刻 `yyyy-mm-dd hh:mm`、または期限からの相対 (例 `-30m`, `-1d`)。複数はカンマ区切り |
| P | 並び順 | 整数 | セクション内の手動並び順 |
| Q | 作成日時 | 日時 | |
| R | 完了日時 | 日時 | 進捗が 100 のときのみ |

- 日付と日時は Excel の日付セル (シリアル値 + 表示形式) で書く。文字列にしない
- 読み込みは見出し名で列を特定する。列順が入れ替わっていても読める
- 未知の列 (ユーザーが Excel で追加した列) は値を保持して書き戻す
- Excel 側で編集された値は読み戻す。型が壊れている行 (日付欄に文字など) は「要修正」としてアプリに表示し、その行はアプリから書き換えない

#### シート「設定」

Qiita 記事の構成に合わせる。アプリが参照・更新する。

- 1 行目: 見出し行 = 1、開始行 = 2、開始列 = A、終了列 = R (アプリが固定値を書く)
- カテゴリ一覧: セクションの表示順を兼ねる
- 担当一覧
- 優先度: 高 / 中 / 低 (固定)
- 祝日はこのシートには置かず、共通ファイルに置く

#### 条件付き書式 (アプリが生成時に付与)

- 進捗 = 100: 行を灰色文字 + 取り消し線
- 終了 < 今日 かつ 進捗 < 100: 終了セルを赤文字

### 3.2 共通ファイル `_PowerToDo.xlsx`

| シート | 列 |
| --- | --- |
| プロジェクト | 名前 / 色 / 並び順 / お気に入り / 受信トレイ (1 件のみ真) |
| ラベル | 名前 / 色 / 並び順 |
| フィルター | 名前 / クエリ / 並び順 (Phase 5) |
| 祝日 | 日付 / 名称 |
| 設定 | 自分の表示名 / 週の開始曜日 / タイムゾーン |

## 4. アプリ構成

```
src/            React + TypeScript + Tailwind (UI のみ。ロジックを持たない)
src-tauri/
  src/
    main.rs       Tauri 起動、command 登録
    commands/     UI から呼ぶ薄い関数 (JSON in / out)
    domain/       Task, Project, Label, Recurrence, Reminder, Query (純粋 Rust、I/O なし)
    store/        xlsx <-> domain 変換、ローカルキャッシュ管理
    sync/         Drive API、OAuth、差分同期、競合処理 (Phase 4)
    scheduler/    リマインダー発火、繰り返しの次回生成 (Phase 3)
    platform/     OS 差の吸収 (キーチェーン、ファイル監視、通知、OAuth リダイレクト)。デスクトップとモバイルで実装を切り替える
design/         pen.dev のデザインファイルと storyboard メモ
docs/           設計書、調査メモ
```

### レイヤ規則

- `domain` は xlsx も Drive も知らない。全ロジックの単体テストをここに集中させる
- `store` は「ファイル全体を読む / ファイル全体を書く」だけ。部分更新はしない
- UI は Tauri command を呼び、返ってきた状態をそのまま描く。今日・近日の判定、営業日数、繰り返し展開はすべて Rust 側で行う
- Rust から UI への変更通知は Tauri の event (`project-changed`, `sync-status`) で送る
- `platform` 以外のモジュールは OS を判定しない

### データの流れ (タスク編集)

1. UI が command `update_task(project, task_patch)` を呼ぶ
2. `store` がメモリ上のプロジェクト状態を更新し、新しい状態を同期的に返す
3. 1 秒のデバウンス後、`store` がそのプロジェクトの xlsx をローカルキャッシュへ書き出す
4. 書き出し後、`sync` が Drive へのアップロードをキューに入れる (Phase 4)

### メモリ上の状態

- 起動時にローカルキャッシュの全 xlsx を読み、全プロジェクトをメモリに保持する (個人用途、数千行で十分軽い)
- 今日・近日・ラベル・フィルターのビューは全プロジェクト横断なので、メモリ上の全タスクに対してクエリを走らせる
- xlsx の外部変更 (Excel で編集、Drive から更新) はファイル監視で検知して再読込する。編集中のプロジェクトに外部変更が来た場合は「ファイルが外部で変更された。再読込 / 自分の変更で上書き」を UI に出す

### ローカルキャッシュの場所 (Tauri の app data dir)

- macOS: `~/Library/Application Support/PowerToDo/`
- Windows: `%APPDATA%\PowerToDo\`
- Ubuntu: `~/.local/share/PowerToDo/`
- iOS / Android: Tauri が返すアプリ専用領域
- 中身: `data/*.xlsx` (Drive と同じ構成)、`sync.json`、`settings.json` (ウィンドウ位置、テーマ)。OAuth トークンは OS キーチェーン

## 5. ドメインの振る舞い

### ビュー

- 受信トレイ: 共通ファイルでフラグを立てた 1 プロジェクト。既定名「受信トレイ」。削除不可
- 今日: 期限が今日以前で未完了のタスク。期限切れは「期限切れ」グループとして上に分ける
- 近日: 今日から先を日付ごとにグループ化。期限なしは表示しない
- プロジェクト: セクション順 → 並び順。完了タスクは既定で非表示、トグルで表示
- ラベル: ラベルが一致する未完了タスク。全プロジェクト横断
- フィルター (Phase 5): Todoist 互換の部分集合のクエリ言語 (`today | overdue`, `p1 & @買い物`, `#仕事 & 7 days`)

### タスク

- サブタスクは多段可 (親No. の連鎖)。親を完了してもサブタスクは自動完了しない
- 完了: 進捗を 100 にし完了日時を記録。取り消しで進捗 0、完了日時を空にする
- 削除: 行を物理削除。サブタスクも削除。確認ダイアログを出す
- プロジェクト間移動: 行をファイル間で移す。No. は移動先で新規割当、親子関係は保つ
- クイック追加の構文: `買い物 明日 p1 #買い物 @急ぎ` → タスク名 / 期限 / 優先度 / プロジェクト / ラベル。日付語は日本語と英語の両方 (`明日`, `来週月曜`, `tomorrow`, `next mon`, `10/20`, `2026-10-20 15:00`)

### 繰り返し (Phase 3)

- RRULE で保持。完了時に次回の期限を計算して同じ行の終了を書き換える (1 行が繰り返し続ける)。完了履歴は残さない
- 自然言語 → RRULE: 「毎日」「毎週月曜」「毎月1日」「平日」「every 2 weeks」など。完了日基準 (Todoist の `毎3日!` 相当) も対応

### リマインダー (Phase 3)

- 発火はアプリ常駐中のみ (デスクトップはトレイ常駐。モバイルは OS のローカル通知にスケジュール登録)
- 通知クリックで該当タスクを開く
- 期限時刻付きタスクには既定リマインダー (期限と同時刻) を自動付与。設定で変更可
- アプリ停止中に時刻を過ぎた通知は、起動時にまとめて 1 件で表示する

### 営業日数

- 開始と終了があるとき、土日と共通ファイルの祝日を除いた日数を書く。どちらか欠ければ空

## 6. 同期 (Phase 4 の概要。詳細は Phase 4 の spec)

同期先は 2 種類。`sync/` に `StorageBackend` trait を置き、`GoogleDrive` と `WebDav` の 2 実装を持つ。ローカルキャッシュ、差分判定、競合処理はバックエンド共通。設定画面と初回起動で「Google Drive / Synology NAS (WebDAV) / 同期しない」を選ぶ。

### 6.1 Google Drive

- 認証: OAuth 2.0 + PKCE。デスクトップはループバック `http://127.0.0.1:<port>`、モバイルはカスタム URL スキーム。スコープは `drive.file` のみ
- OAuth クライアント ID (デスクトップアプリ用) はアプリに同梱する。ユーザーは設定画面の「Google でログイン」を押すだけで、ID を入力しない (2026-10-13 変更)
- Drive 側: `PowerToDo/` フォルダ (初回に作成または既存を選択) 配下に `*.xlsx`
- 同期単位はファイル。`sync.json` に各ファイルの Drive fileId / Drive modifiedTime / Drive md5 / ローカル保存時ハッシュを持つ
- タイミング: 起動時、ローカル保存の 5 秒後、5 分間隔、手動。ネット不通時は黙ってスキップ
- 判定 (ファイルごと)
  - ローカルのみ変更 → アップロード
  - Drive のみ変更 → ダウンロードして再読込
  - 両方変更 → modifiedTime が新しい側を採用。負けた側を `<名前> (競合 yyyy-mm-dd hhmm).xlsx` として同フォルダに保存し、UI にバナー。ユーザーが手で統合
  - Drive で削除 → ローカルを `archive/` に移動して一覧から外す
- ステータスバーに 同期中 / 同期済み (時刻) / オフライン / エラー を表示

## 7. エラー処理

- xlsx 読み込み失敗 (壊れたファイル、ロック中): そのプロジェクトだけ「読み込めません」と表示し、他は動く。該当ファイルは上書きしない
- 書き込み失敗 (Excel が開いていてロック、Windows で多い): 3 回リトライ。失敗ならバナーを表示し、メモリ上の変更は保持して次の保存で再試行
- 行の型不整合: その行を「要修正」マークで表示し、Excel で直すよう促す。アプリからの編集は不可
- 同期エラー: ステータスバーに表示。ローカルの編集は止めない

## 8. テスト方針

- `domain`: 単体テスト (クエリ、日付解析、RRULE 次回計算、営業日数、クイック追加構文)
- `store`: 往復テスト (domain → xlsx → domain で同値)、Qiita 形式の手作りファイルの読み込み、未知列の保持、型不整合行の検出
- `sync`: Drive API をモック HTTP に差し替え、競合シナリオをテスト
- UI: Phase 1 は手動確認。Phase 2 以降で Playwright + tauri-driver を検討
- モバイル: Phase 6 で iOS シミュレータと Android エミュレータで手動確認
