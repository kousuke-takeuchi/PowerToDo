## 1. 目的と範囲

所有者の言葉 (2026-10-25):
- 右からのペインで詳細編集ではなく、モーダル表示での編集 (Todoist と同じ)
- コメントも保存できるようにする
- コメントは Excel では読まず、アプリだけが読む。タスクごとに jsonl を作成すればよい

2 つに分け、設計書は 1 つ、実装の PR は 2 つにする (①a の次に ①b)。

**①a タスクの詳細ダイアログ (デスクトップ)**
- 右の詳細欄 (`TaskDetailPanel`、幅 400) をやめ、画面中央のダイアログにする
- 前後のタスクへの移動
- プロジェクト・セクションの変更とラベルの付け外しを、ダイアログからできるようにする
- 今日・近日・ラベルの画面から開いても、その画面に留まる

**①b コメント**
- タスクごとにコメントを書き、直し、消せる
- 端末をまたいで同期する

含まないもの:
- iPhone の画面 (iPhone は同じコメントのファイルを読めるようにするが、画面は後の作業)
- 添付ファイル、コメントへの返信、メンション、絵文字の反応
- 期限 (Todoist の Deadline)、位置情報、担当者の欄 (PowerToDo のデータに無い)
- Todoist の「…」のうち、削除以外 (複製、リンクのコピー、新しいウインドウで開く など)

成功基準:
- 行をクリックすると、画面中央のダイアログが約 0.1 秒で出て、後ろが暗くなる。開いた画面のまま
- 「∧」「∨」(と `k` / `j` のキー) で、画面に出ている順の前後のタスクに、中身がすぐ切り替わる
- ダイアログから、別のプロジェクトやセクションへ移せる。ラベルを付け外しできる
- コメントを書くと、別の端末に 1 分以内に届く (30 秒ごとの確認と同期で)
- 2 台で同じタスクにコメントを書いても、両方のコメントが残る

## 2. ダイアログの見た目と動き (①a)

### 2.1 大きさと配置
- 画面中央。幅は `min(864, ウィンドウ幅 - 32)`、高さは `min(820, ウィンドウの高さ - 64)`
- 後ろは `--color-scrim` で暗くする。開くとき約 0.1 秒で薄く出し、閉じるとき約 0.08 秒で消す (Todoist の測定)
- 角の丸み 12、影は `--shadow-dialog`
- 幅 750 未満 (④ の狭い表示) では、右の欄を左の欄の下に回す (縦 1 列)

### 2.2 上の帯 (高さ 48、下に区切り線)
- 左: プロジェクトのアイコンと「プロジェクト / セクション」。押すとプロジェクトの画面へ移り、ダイアログを閉じる
- 右: 「∧」前のタスク、「∨」次のタスク、「…」メニュー (削除)、「×」閉じる
- 前後が無いとき (先頭・末尾)、その矢印は押せない

### 2.3 左の欄
- チェック (18) と、大きな名前 (20、太字)。名前はその場で直せる (今の詳細欄と同じく、Enter か外を押すと保存)
- 説明 (今の備考)。空なら「説明」と薄く出し、押すと書ける
- サブタスク: 一覧と「+ サブタスクを追加」(今の詳細欄と同じ動き)
- コメント (①b): 一覧と入力欄。①a の時点では入力欄を出さない

### 2.4 右の欄 (幅約 260、背景 `--color-bg-sidebar`)
上から順に、区切り線で分ける。

| 項目 | 押したとき |
|---|---|
| プロジェクト | プロジェクトとセクションの一覧から選ぶ (①a で新しく変えられるようにする)。今の `move_task` を使う |
| 日付 | 今の日付ピッカー |
| 優先度 | 今の優先度ピッカー |
| ラベル | ラベルの一覧から付け外し、新しい名前も書ける (①a で新しく変えられるようにする) |
| リマインダー | 今のリマインダーピッカー |
| 繰り返し | 今の繰り返しピッカー |

### 2.5 開き方・閉じ方・前後の移動
- 開く:
  - 行をクリック、または行を選んで Enter
  - 今日・近日・ラベル・検索の画面から開いても、その画面のまま開く
  - 今は、プロジェクトの画面へ移ってから右の欄を開いている
- 閉じる:
  - Esc、「×」、暗い所を押す
  - 閉じたら、開く前に選んでいた行にキーボードの選択を戻す
- 前後の移動:
  - その画面に出ている順 (④ の行の選択と同じ順) の前後へ移る
  - サブタスクは、開いていれば並びに入る
- 前後へ移るときの動きは無し。中身をすぐ入れ替える (Todoist の測定)
- キー: `k` 前、`j` 次。ダイアログが開いている間だけ効く。名前や説明を書いている間は効かない
- ダイアログの中で、タスクを完了・削除・別のプロジェクトへ移した場合:
  - ダイアログは開いたまま次のタスクへ移る
  - 次が無ければ閉じる

### 2.6 今の右の詳細欄
- `TaskDetailPanel` の中身 (項目の行、ピッカー、サブタスク) は、ダイアログの部品として使い回す
- `AppShell` の `panel` (幅 400) は使わなくなるので外す

## 3. コメント (①b)

### 3.1 置き場所と名前
- データフォルダの `_comments/` フォルダ。1 つのタスクに 1 ファイル `<プロジェクト>.<No>.jsonl`
  - 例: `_comments/仕事.12.jsonl`
  - プロジェクト名にドットがあっても、末尾の `.<数字>.jsonl` で区切れる
- フォルダは `_comments/` の 1 段だけにする
  - 会話の案は `_comments/<プロジェクト>/<No>.jsonl` だった
  - プロジェクトごとのフォルダにすると、同期のたびと 30 秒ごとの確認のたびに、フォルダの数だけ一覧を取ることになる (NAS は PROPFIND がプロジェクトの数だけ増える)
  - 1 段なら、一覧は 1 回増えるだけで済む (§8 の決定ログ)

### 3.2 中身 (JSON Lines、UTF-8)
1 行が 1 つの出来事。書き足すだけで、前の行は書き換えない。

```json
{"id":"01JB2X…","op":"add","at":"2026-10-25T21:04:05+09:00","author":"たろう","text":"見積もりを送った"}
{"id":"01JB2Y…","op":"edit","target":"01JB2X…","at":"2026-10-25T21:10:00+09:00","author":"たろう","text":"見積もりを送った (税込)"}
{"id":"01JB2Z…","op":"delete","target":"01JB2X…","at":"2026-10-25T21:12:00+09:00","author":"たろう"}
```

- `id`: その行の ID。時刻順に並ぶ一意の文字列 (ULID 相当)
- `author`: 設定の表示名
- `at`: その端末の時刻 (タイムゾーン付き)
- 表示するときは、行を `id` の順に読み、`add` を並べ、`edit` で本文を差し替え、`delete` で消す
- 読めない行は飛ばす (他の行は表示する)

### 3.3 画面
- 左の欄の下に、コメントの一覧 (古い順):
  - 書いた人、日時 (「10月25日 21:04」)、本文
  - 直したものには「(編集済み)」
- 一覧の下に入力欄。Enter で送る (Shift+Enter で改行)。IME の変換中の Enter では送らない
- 自分のコメントにマウスを乗せると「編集」「削除」。削除は確かめてから
- 行の 2 段目に、コメントの数 (吹き出しのアイコンと数)。0 のときは出さない

### 3.4 同期
- 同期の対象を広げ、`_comments/*.jsonl` も含める。今はデータフォルダ直下の `*.xlsx` だけが対象
- 相手側にも `_comments/` フォルダを作り、その中を一覧に加える:
  - NAS: `_comments/` の PROPFIND (Depth 1) を 1 回足す
  - Drive: `_comments` のフォルダ ID を探して、その中を一覧に足す
- 30 秒ごとの確認の指紋にも、`_comments/` の中のファイルを含める
- 両側で変わったとき:
  - 両方の行を `id` で合わせ、重なりを除いて `id` の順に並べた中身を、両側に書く
  - 書き足すだけなので、どちらの行も失われない
  - 土台 (前回の同期の中身) も競合コピーも要らない
- 片側で消えた (相手側に無い) ファイル: プロジェクトの archive と同じ扱い (§3.5)

### 3.5 プロジェクトとタスクの変化に合わせる
- プロジェクトの名前を変えた: そのプロジェクトのコメントのファイルの名前を `<新しい名前>.<No>.jsonl` に変える
- プロジェクトを削除・archive した: そのプロジェクトのコメントのファイルを `archive/` に移す
- タスクを削除した: そのタスクのコメントのファイルを `archive/` に移す
- タスクを別のプロジェクトへ移した:
  - 新しい No. になるので、ファイルを `<新しいプロジェクト>.<新しい No.>.jsonl` に移す
  - 移した先に同じ名前があれば、行を合わせる
- 同期でタスクの No. を振り直した (タスク単位で合わせる §4.3): ファイルを新しい No. に移す
  - 振り直されるのは、まだ相手に届いていない手元のタスクなので、手元のファイルだけを移せばよい

### 3.6 書けないとき
- コメントのファイルが書けない (権限、ディスク): 帯に出し、入力欄の文字は残す
- 読めない: そのタスクのコメントは「コメントを読み込めませんでした」と出す。タスクの他の項目は使える

## 4. iPhone
- iPhone も同じ `_comments/` を同期で受け取り、保存する
- 画面に出すのは後の作業。ただし、iPhone でタスクを削除・移動したときも §3.5 のとおりファイルを動かす (仕組みは共通の Rust のコード)

## 5. 作る場所 (目安)
- Rust:
  - `store/comments.rs`: 読む、書き足す、名前を変える、archive に移す、行を合わせる
  - `sync/` で `_comments/` を対象にする: 一覧、アップロード、ダウンロード、合わせ方
  - `ProjectStore` のプロジェクトの名前の変更・削除、タスクの削除・移動から、コメントのファイルを動かす
  - コマンド: `list_comments(project, no)`、`add_comment`、`edit_comment`、`delete_comment`
  - コメントの数は `ProjectView` に載せる
- 画面:
  - `TaskDialog` (新しい部品)
  - `TaskDetailPanel` の中身を分けて使い回す
  - `Main` から右の欄をなくす
  - 前後の移動は `useRowFocus` の表示順を使う

## 6. テスト

自動:
- 合わせ方: 両側に別の行 → 両方残る。同じ行 → 1 つ。読めない行 → 飛ばして残りは合わせる
- 表示の組み立て: `add` / `edit` / `delete` から一覧を作る。順番が前後しても同じ結果
- ファイルの名前: `仕事.12.jsonl` と `a.b.3.jsonl` を正しく読む。数字で終わらない名前は対象外
- 同期 (今の `MemoryBackend` の 2 台のテストの形):
  - 2 台でコメントを書く → 両方に両方のコメント
  - 片方で書いて 30 秒以内の確認で届く
- プロジェクトの名前の変更・削除、タスクの削除・移動、No. の振り直しで、ファイルが動く
- 前後の移動の順番 (画面の表示順から前後を決める純粋な関数)

手動 (PR 本文のチェックリスト):
- 今日の画面から行を開く → ダイアログ、画面は今日のまま。∧∨ と j/k で前後へ。Esc で閉じて同じ行が選ばれている
- ダイアログからプロジェクトを移す、ラベルを付け外す
- コメントを書く・直す・消す。Mac と Windows (か iPhone と PC) で、両方で書いて両方残る
- プロジェクトの名前を変えてもコメントが残る
