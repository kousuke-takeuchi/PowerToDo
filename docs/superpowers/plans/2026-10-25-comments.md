# Comments (①b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Save comments per task as app-only JSON Lines files in `_comments/<project>.<No>.jsonl`, sync them between devices (merging both sides' lines by id), keep them attached when projects or tasks are renamed, moved, deleted or renumbered, and show them in the task dialog with a count on the row.

**Architecture:**
- A pure module `store/comments.rs` holds the line format, the merge (union by id), the view that turns events into comments, and the file names.
- The store writes comment files next to the project files, in `data/_comments/`, and moves them when projects or tasks change.
- Sync handles comments in a second pass inside the same run:
  - The backends get a comments-folder variant of list / upload / archive.
  - The per-file decision reuses `decide()`, with records kept in the same `sync.json` under `_comments/<name>` keys.
  - A both-sides change is merged by line id, so there is never a conflict copy.
- The 30 s check includes the comments listing in its fingerprint.

**Tech Stack:** Rust 2024 (serde_json, rand 0.9 already in Cargo.toml), Tauri 2 commands, React 19, `wiremock` for WebDAV tests, `MemoryBackend` for engine tests.

**Spec:** `docs/superpowers/specs/2026-10-25-task-dialog-and-comments-design.md` §3, §4, §6.

**Prerequisite:**
- Merge #49 (①a dialog) first, because the comment UI goes into `TaskDialog`.
- Start the implementation branch from origin/main after that.

## Global Constraints

- File: `data/_comments/<project>.<No>.jsonl`, UTF-8, one JSON object per line, `\n` line ends. Parse the name with `rsplit` on the last two dots (project names may contain dots).
- Line:

```json
{ "id": string, "op": "add" | "edit" | "delete", "target"?: string, "at": RFC3339 with offset, "author": string, "text"?: string }
```

- `id` sorts by time:
  - Format `format!("{millis:013}-{rand:016x}")`: milliseconds since the epoch, zero-padded, then 64 random bits from `rand`.
  - Never reuse an id. Lines are only appended, never rewritten, except that a sync merge rewrites the file as the sorted union.
- View: read lines in id order.
  - `add` creates a comment.
  - `edit` replaces its text (edited = true).
  - `delete` removes it.
  - Lines that do not parse, and `edit` / `delete` whose `target` is missing, are skipped.
- Author = the settings display name (`store.settings().display_name`). Only the author's own comments can be edited or deleted in the UI.
- Sync:
  - Comment files are never conflict copies, and never go through `BaseStore`, `stage_download` or the workbook reload.
  - A both-sides change writes the union to both sides.
  - The Suspect (wiped-side) guard ignores comment files.
- Backends: NAS uses one more PROPFIND (Depth 1) on `_comments/` per listing. Drive uses one more `files.list` on the `_comments` folder (found or created with `appProperties` kind `comments`).
- iOS uses the same Rust code. The iOS UI is not in this plan.
- Never print or commit `src-tauri/google-oauth.json`. No `-v` builds. Commits have no `Co-Authored-By` or any AI trailer. Sample names: たろう, 仕事, 買い物.

## Review Focus

1. **Project rename on one PC while the other PC adds a comment.** After both sync, the comment is under the new name and nothing comes back under the old name. Test: `rename_then_comment_on_other_pc` (Task 6).
2. **Delete a task whose comment file was never synced.** The local file goes to `archive/` and no remote action fails. Test in Task 3 (`delete_task_archives_comments`) and Task 6.
3. **Merge renumbering of a task that has comments.** The local comment file follows the task to its new No. before upload, and the remote's file under the old No. (another task) is untouched. Test: `renumbered_task_keeps_its_comments` (Task 6).
4. **A wiped `_comments/` folder on one side.** Comments are not removed elsewhere, because the guard ignores them. A missing remote folder is treated as empty, not as an error. Test: `missing_remote_comments_folder_is_empty` (Task 4) and the engine test in Task 6.
5. **Two lines with the same id but different content** (a corrupted or hand-edited file). The merge keeps one, chosen deterministically (the one that sorts first by full line text). Test: `merge_same_id_keeps_one` (Task 1).

## PR checklist (manual)

- [ ] Write, edit, delete a comment; the row shows the count
- [ ] Mac and Windows (or iPhone and PC): both comment on the same task, both sync, both comments on both
- [ ] A comment reaches the other PC within a minute (30 s check)
- [ ] Rename a project, move a task to another project, delete a task: comments follow or go to `archive/`
- [ ] NAS and Google Drive both create `_comments/` on the first comment
- [ ] Two PCs add the same No. to the inbox and comment: after sync each comment stays with its own task
