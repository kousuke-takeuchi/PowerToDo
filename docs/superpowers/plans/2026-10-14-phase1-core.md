# Phase 1: 土台 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phase 0.5 の React 画面を Rust 側の実データにつなぎ、ローカルの xlsx だけでプロジェクト / セクション / タスク (サブタスク含む) の CRUD とクイック追加ができる Tauri アプリにする。

**Architecture:** Rust (`src-tauri/src/`) に `domain` (I/O なし) / `store` (xlsx 全体の読み書き + メモリ保持 + デバウンス保存) / `commands` (薄い Tauri command) / `platform` (ダイアログ、パス) を置く。UI は `src/api/` の薄い invoke ラッパーと `src/app/` の配線層だけを足し、Phase 0.5 の view は callback props を追加して使う (Storybook はモックのまま動く)。command の戻り値は常に最新の `ProjectView` 全体。

**Tech Stack:** Rust 2024 edition (1.97)、Tauri 2、`calamine` 0.36、`rust_xlsxwriter` 0.99、`chrono` 0.4、`serde` / `serde_json`、`thiserror`、`tempfile` 3、`tauri-plugin-dialog` 2 (+ npm `@tauri-apps/plugin-dialog` 2.8)、既存の React / TypeScript / Vite / Tailwind / Storybook。バージョンは 2026-10-14 の `cargo search` / `npm view` の結果。`cargo add` の解決結果を Task 1 の report に記録する。

**Spec:** `docs/superpowers/specs/2026-10-14-phase1-core-design.md` (全体設計 `docs/superpowers/specs/2026-10-13-powertodo-overall-design.md` §3 の列定義、§5 の振る舞い)

## Global Constraints

- 作業ブランチ `feature/phase1-core` (origin/main から `--no-track`)。push は `git push origin feature/phase1-core:refs/heads/feature/phase1-core`。PR base は main。コミットに attribution trailer を付けない
- `domain` は `std` と `chrono` / `serde` 以外に依存しない (ファイル・Tauri・xlsx を知らない)。`store` は「ファイル全体を読む / 書く」だけ。`commands` にロジックを書かない
- JSON の型名・フィールド名は `src/types/model.ts` (`Task`, `Project`, `Section`, `Label`) と一致: serde は `#[serde(rename_all = "camelCase")]`、`Option` は `skip_serializing_if = "Option::is_none"`、日付は `"YYYY-MM-DD"`、日時は `"YYYY-MM-DDTHH:MM"` の文字列
- xlsx の列は全体設計 §3 のとおり (A No. 〜 R 完了日時、見出し名で特定、未知列は保持)。保存は一時ファイルに書いて `rename`。削除は `archive/` へ移動
- 「受信トレイ」はプロジェクト名固定、削除不可
- 全 command は `Result<T, AppError>`、`AppError { kind, message }` を JSON で返す
- TDD: Rust は失敗するテストを先に書く。`cargo test` と `cargo clippy -- -D warnings` と `cargo fmt --check` を各タスクの終わりで通す。UI は `npx tsc --noEmit` と `npm run build` と `npm run build-storybook` を通す (Storybook が壊れていないこと)
- 実在の識別子をサンプルに使わない (たろう / user@example.com)
- `npm run tauri dev` の手動確認は Task 10 で行う。それまでは `cargo build` で Rust 側のコンパイルだけ確認する

## Review Focus

1. Excel で「終了」列に文字列 (例 `来週`) を入れた行 → その行だけ `invalidRows` に入り、他の行は普通に読める。保存してもその行の元の値は壊れない → Task 4 のテスト `invalid_date_cell_is_reported_not_dropped`
2. 2 つの保存要求が 1 秒以内に連続したとき、書き出しは 1 回で、最後の状態が書かれる → Task 5 のテスト `debounce_coalesces_saves`
3. 保存中に xlsx がロックされている (Windows で Excel が開いている) → 3 回リトライ後に `save-status: error` で止まり、メモリの変更は失われない。次の変更で再試行される → Task 5 のテスト `save_failure_keeps_dirty_state` (書き込み先をディレクトリにして失敗させる)
4. クイック追加で `#` や `@` を含むが対応するプロジェクト / ラベルが無いとき → タスク名にそのまま残し、エラーにしない → Task 3 のテスト `unknown_project_stays_in_title`
5. 親タスクを削除すると子孫も消え、No. は再利用されない (次の採番は旧最大 + 1) → Task 5 のテスト `delete_parent_removes_descendants_and_keeps_numbering`
