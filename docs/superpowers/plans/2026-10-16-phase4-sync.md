# Phase 4 (同期: Synology NAS via Tailscale・Google Drive) 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ローカルのデータフォルダを、Synology NAS (アプリ同梱の Tailscale サイドカー経由の WebDAV) か Google Drive のどちらか 1 つにファイル単位で同期する。

**Architecture:** 同期コア (`sync/mod.rs` の純関数 `plan()` と実行 `run_once()`、`sync.json`) が `StorageBackend` trait 越しに WebDAV / Drive を使う。NAS へは cgo なしの Go サイドカー `powertodo-tailnet` (tsnet) の SOCKS5 を通す。ダウンロードは Phase 2 の自分の書き込み記録と `reload_external` で取り込む。UI は設定「同期」ペイン、サイドバーの状態、競合の帯、初回起動ステップ 2。

**Tech Stack:** Rust 2024 (Tauri 2.12, reqwest 0.13 `rustls`/`json`/`multipart`/`socks`, keyring 4.2 `v1`, quick-xml 0.42, sha2 0.11, base64 0.23, rand 0.10, url 2.5, percent-encoding 2.3, wiremock 0.6 dev), Go (tailscale.com/tsnet, 最新の安定版 v1.104.x), React 19 + TypeScript, Storybook 10。

**Spec:** `docs/superpowers/specs/2026-10-16-phase4-sync-design.md` (以下「仕様」)。参考実装 `~/Documents/InfoDesk` (`app/src-tauri/src/tailnet.rs`, `crates/core/src/sync/webdav.rs`, `app/src-tauri/src/sync/oauth.rs`, `app/src-tauri/build.rs`, `app/src/views/settings/NasGuideDialog.tsx`) — 読んでよいがコピーはせず、PowerToDo の構造に合わせて書く。

## Review Focus

1. 同期中のダウンロードが Phase 2 の外部変更検知に「外部変更」と誤判定されない (書き込み直後の `record_written`) — Task 4 `downloaded_file_is_not_an_external_change`
